Privacy Policy

Effective date: November 28, 2026 · App: Sequmio (com.sequmio.givlse)

This policy describes the data used by Sequmio, an Android app-testing utility developed by Vladislav Girskii (GIVLSE).

1. What Sequmio does

Sequmio helps you create test plans that open selected installed Android apps one after another, each for a specified duration. It supports repeated runs and locally stored test history.

2. Information accessed on your device

  • Launchable installed apps: application display names, package identifiers and launcher activities to show a list of apps that you can select.
  • Test plans: selected apps, execution order, per-app durations, repeat options and time limits.
  • Foreground app events: the active app's package identifier and window-change timestamps detected by the user-enabled Android Accessibility Service.
  • Execution history and reports: local time-stamped run events, app identifiers, test timings, retry counts, PASS/FAIL status and structured session reports (JSON/CSV format).
  • Consent setting: a local record of your acknowledgement of Sequmio's Accessibility Service disclosure.

These items are used solely to run the test plan you requested, check app switching, and display results.

3. Accessibility Service

Sequmio requests use of Android's Accessibility Service to launch selected apps, inspect visible UI nodes during user-selected scenarios, perform deterministic test actions and detect which app is active. This service is enabled only by you in Android system settings after a prominent disclosure and an explicit consent step.

During an explicitly started E2E run, Sequmio may inspect visible UI element text, view IDs and accessibility descriptions to find a requested test target, and perform predefined taps, swipes, Back and text input. You may separately start a UI event recorder for your own app. It captures available button-click selectors, approximate scrolls and text-field identities as locally stored scenario steps, never raw touch streams or the characters typed. Password fields are excluded, and text entry steps require manually added non-sensitive test data. The UI recorder does not take screenshots or record audio/video, and Sequmio does not automatically approve Android permission dialogs.

Optional automatic Screenshot Evidence (v1.3.6). Disabled by default and separately enabled in Settings by a signed-in tester. On Android 14 or later, when an explicitly started test has a confirmed failed assertion, Sequmio can capture only the tested app's active window. It does not capture the full display, protected windows, or windows with detected editable/password fields. Screenshots can still contain sensitive visible information. If you separately opt into automatic screenshot sharing, the image is sent to the tested app's report owner without individual review. Only use non-sensitive test accounts and data. The old local-capture consent does not enable automatic sharing.

You can revoke this access at any time in Android Settings → Accessibility. Automatic app cycling will not work without this service.

4. Optional Google account

Sequmio V0.5 introduces optional sign-in with Google through Android Credential Manager and Firebase Authentication, available only when the developer has configured a Firebase project. You may continue using the local Runner without signing in.

If you choose to sign in, Google and Firebase process your authentication information. Sequmio stores your Firebase user ID, display name, email address, profile image URL and last-login time in a Firebase Cloud Firestore profile document, protected by account-scoped rules. This account data is transmitted to Firebase/Google infrastructure; it is not used for advertising or analytics. Local test plans and logs remain on your phone; sanitized reports may be uploaded only with separate report-sharing consent.

When configured, App List displays published developer-submitted listings containing package name, app name, description, public Google Group/Play links, owner display name and scenario JSON. Signed-in developers may publish these fields to Firestore. Join stores the tester's user ID, package name, join timestamp and self-reported completion state; Sequmio cannot independently verify membership in Google Groups or Google Play testing. Your local My App draft remains on your device until explicitly published.

5. Foreground execution and notifications

While you run a test, Sequmio uses a user-initiated Android foreground service and an optional system notification with a Stop action. The service uses a partial CPU wake lock to keep timers responsive, but cannot prevent other apps' screens from locking. Android notification access is optional and can be changed in Settings. A separate, opt-in daily reminder uses the local calendar, selected reminder time and installed joined-app testing activity. The reminder does not start tests automatically. The QA progress tracker records testing dates locally for the signed-in account; it is not verification by Google Play.

6. Storage, data sharing and security

Test plans, consent setting, My App drafts and execution history are stored locally on your device using Android SharedPreferences. Sequmio does not automatically transmit local test records unless you explicitly enable QA report sharing in Settings. Sharing is OFF by default and requires a Google account. When enabled, sanitized metadata is uploaded to Firebase for the owner of the tested app: your account tester ID, device model/manufacturer, Android API version, tested app version, scenario name/category/version, step PASS/FAIL/SKIPPED, and timing. Automatic metadata reports do not include screenshots, screen contents, typed text or credentials. Optional automatic screenshot sharing is separately consented and described below. The app has no advertising or behavioral analytics. Developers can export received technical report metadata from their QA Dashboard as JSON or CSV. No personal information is sold.

Because this information is stored locally, anyone with access to your unlocked device may be able to view the test log in the app. Protect your device with Android's normal screen-lock security.

7. Distributed QA reports and daily digests

With separate opt-in to automatic Screenshot Evidence and QA report sharing, after a confirmed failed assertion, the image and its failed report ID, app ID, step number, tester UID, owner UID and sharing time are stored in Firebase Cloud Firestore. Only the submitting tester and the owner of that report can access it, subject to the server rules. Up to 20 pending screenshots per account, each up to 200 KB, may temporarily reside in private app storage for automatic retry. They are removed after confirmed upload, consent revocation or a 24-hour expiry (cleanup is subject to Android scheduling). No images appear in the tester's gallery or History. Legacy local screenshots are removed on upgrade without uploading. Either participant can delete the shared copy through applicable account/data deletion procedures; the report owner can delete it in Dashboard. Previously shared images may remain until removed or account deletion/administrative cleanup; clearing local app storage does not remove a cloud copy. A developer may retain a copy outside Sequmio if they separately capture or export information.

In Sequmio v1.1, report sharing is disabled by default. If you consent, WorkManager uploads technical run results when connected and retries interrupted uploads. Reports are visible to the submitting tester and the developer who owns the tested app. Test steps are reported as metadata only. The developer can see device and app version coverage as well as comparison of PASS/FAIL between builds.

A scheduled Firebase server function can create daily summaries of the previous UTC day. Developers may optionally enable email summaries to their Google account email when the developer configures a mail provider. Without such deployment, no daily email is sent. No false claim of automatic daily delivery is made.

Cloud QA reports and daily digests remain until account deletion or administrative cleanup. Local plans and reports remain on the device until cleared. Google/Firebase and any configured email service process information necessary for the selected service.

8. Retention and deletion

The app keeps selected test settings until you change or delete the app's local data. Its execution log keeps recent events, and local structured reports are limited to the most recent 40 sessions. You can delete locally held Sequmio data by clearing its storage in Android Settings or uninstalling the app. You can delete your Sequmio cloud profile, published listings and tester memberships from Settings → Profile → Delete my Sequmio account. Signing out alone does not delete cloud data. For deletion requests outside the app, see Account Deletion. Firebase may require you to sign in again before deletion completes.

9. Children

Sequmio is designed for developers and app testers and is not directed at children.

10. Changes to this policy

If future versions add full gesture capture, automatic upload of screen content or other new data processing, this policy and the related in-app disclosure will be updated before those features are introduced.
