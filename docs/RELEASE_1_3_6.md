# Sequmio 1.3.6 — Automatic Screenshot Evidence
- Supersedes manual review workflow in 1.3.5 (build 38); versionCode 39.
- New separate opt-in in QA Reports and Settings > Screenshot Evidence. Prior local-only consent does not authorize automatic transmission. Default OFF. Existing metadata-only consent is unchanged.
- At a required assertion FAIL, capture the selected community/owner app window on Android 14+ only, while the user-started run is active, with existing privacy guards. No full display, protected windows or detected editable/password fields.
- Capture -> bounded private no-backup temporary queue -> WorkManager -> existing failed case metadata report -> online Firestore transaction -> delete temporary JPEG after server acknowledgement. No History review, share or delete buttons for tester. Old local-only screenshots are removed on upgrade and never uploaded.
- Metadata upload stays independent. Pending evidence retries up to 10 retries, 24h expiry, 20 files/account, max 200 KB. Android may delay expiry work; cleanup also runs when queue accessed. No guarantee of image on unsupported OS, protected windows, failed captures, expired queue or server denial. Disabling sharing/sign-out clears pending queue, revokes new captures and cancels jobs; a transaction already accepted by the server may have completed. Images previously shared remain subject to deletion.
- Dashboard reads only cloud image; distinguishes missing, decoding and server permission errors. Developer retains delete shared copy.
- Firebase deployment gate unchanged: updated firestore.rules and firestore.indexes.json must be deployed before rollout. Main remains 1.3.4 pending acceptance. Update Play Accessibility/Data Safety disclosures for automatic image sharing before rollout.
